## CORRECTION (Manager 21:31, verified by an executed interleaving): the 15.1 "no second accepted transition" row was overclaimed
My batch-2 row said the acceptor "replays state before every retry" so a retry cannot mint a second accepted transition. FALSE as written: `_accept` replayed state, then ran claim/port/mint work, then read a NEW head and appended against it, so a rival public run of the same package that landed in between was legitimised by the advanced HEAD (two CANONICAL_ACCEPTED records at seq 1/2; replay then refuses ILLEGAL_TRANSITION). The row's wording is withdrawn.
FIX (this PR): the acceptor pins one HEAD basis BEFORE its replay, decides only on records through that basis, and CASes against that same basis (never a refreshed head). A rival commit makes the CAS fail (HeadMismatch); the retry re-reads and the exact same package returns the existing acceptance (no remint), a different manifest for the version still refuses VERSION_CONFLICT (`test_pipeline`). Tests: `test_r52_acceptance_race` (the Manager's interleaving negative with same-journal replay and one acceptance; sequential control; no-port control). Mutant "append against a freshly read head" is KILLED; mutant "unbounded replay but pinned CAS" survives and is behaviour-equivalent (the CAS fails and the retry reaches the same result).
The separated acceptor path (`ops/separated_handlers.accept`) calls the same `pipe._accept`, so it carries the fix; it was not given its own interleaving test.
REVIEW of the same stale-state/fresh-HEAD pattern in other append sites (own reading, not new mutants): `tracker/publication._commit` reads HEAD before the state (older head, newer state: the CAS fails closed); `coordination/lifecycle_framework.apply` and `core/tracker_core._commit` decide and CAS on one pinned head; `tracker/evidence_resolver.put/revoke` append with a fresh head but make no decision from prior state; `tracker/sim_publication_path.commit` appends to the side journal with a fresh side head when none is pinned, but the decision is on the owning journal whose head is recorded in the body and guarded downstream (documented fail-closed design, R51); a pinned `expected_side_head` is available.
