## 5. Typed ancestry relation / authority proposal
Logical owner of the verification: the Tracker verification/closure function, CONSUMING source-owned ML/model/generation/fit relations; it does not author them. Implemented candidate (PR #106): `AncestryBinding(record, subject_node, upstream_model_node, upstream_generation_node, fit_ref_nodes{generation -> node})` returned by an explicit resolver; intake derives the closure, requires the claimed subject, reaches the claimed upstream nodes and every fit-reference node, and requires a content-carrying learned/model-generation edge; otherwise FAIL, and UNKNOWN (held) when unbound. Fit-reference currency stays the separate FIT_ANCESTRY dimension.
Proposed typed relations the source owners would have to supply (none supplied today): (1) feature -> UPSTREAM_MODEL_ID (LEARNED_DERIVED_MODEL_EDGE); (2) model -> UPSTREAM_GENERATION_ID (MODEL_GENERATION_INPUT_EDGE); (3) generation -> each fit reference (FITTED_TRANSFORM_EDGE); (4) the mapping from package strings to closure node ids, as a source-owned lookup, never string/number equality. Authority question for the owners: who appoints the resolver and which registry is the node-id namespace.
Policy pin (not silently changed): `ANCESTRY_CLOSURE` is a failure label outside the pinned dimension list; the report may therefore name a failed dimension the policy hash does not list. Two compliant options: (A) documented derived hold, as now: existing dimensions stay, the label is a reason-class, and no report claims a PASS from the label's absence; (B) explicit versioned successor policy (same ID, VERSION 2, dimension list plus ANCESTRY_CLOSURE) with compatibility evidence: V1 reports keep V1 hash and cannot carry an ancestry-closure verdict for learned-derived builds; readers fail closed on an unknown policy version. B's hash needs the domain-separation tag for V2, which no source defines (the V1 tag embeds "V1"): that tag is the decision input; I did not compute or adopt a V2 hash. Recommendation: stay on A until the owners decide B.
